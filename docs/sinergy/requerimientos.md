# Especificación de Requisitos de Software (SRS):

- Qué es: El documento maestro que contiene todos los requisitos. Puedes basarte en estándares como el IEEE 830 para estructurarlo. Se divide en dos partes fundamentales:

1. **Requisitos Funcionales**: Describen qué debe hacer la aplicación. Son las funcionalidades y acciones específicas que el usuario puede realizar (ej. "El usuario debe poder iniciar sesión con su correo", "La app debe permitir agendar una cita").

2. **Requisitos No Funcionales**: Describen cómo debe hacerlo. Son las características de calidad, rendimiento y seguridad que no son visibles para el usuario, pero son cruciales para el éxito (ej. "La app debe cargar en menos de 2 segundos", "Todos los datos del usuario deben estar encriptados", "Debe ser escalable para soportar 10,000 usuarios").

> **Consejo**: A cada requisito asígnale un identificador único, una descripción, y una prioridad (ej. Alta, Media, Baja).
